## `createCue(options?)`

`createCue()` creates one isolated overlay environment. Its returned Cue instance is the only place to create overlays and the only provider that can render them.

```tsx
const cue = createCue({
  backdrop: OverlayBackdrop,
  components: {
    wrapper: OverlayWrapper,
    footer: OverlayFooter,
  },
});
```

`components` is an application-defined map. Cue does not reserve keys such as `header` or `footer`. The exact map is inferred in every overlay callback.

`backdrop` is different. Cue renders it once for the visible stack. Individual overlays do not render it.

When the backdrop comes from a shadcn Dialog wrapper, use the Dialog content component without its built-in backdrop so the provider remains the only backdrop owner:

```tsx
<Dialog open={ctx.open} onOpenChange={ctx.onOpenChange}>
  <DialogContent showBackdrop={false}>...</DialogContent>
</Dialog>
```

## `cue.OverlayProvider`

```tsx
<cue.OverlayProvider>{children}</cue.OverlayProvider>
```

The provider renders children, every visible overlay, and one shared backdrop while at least one instance is open. An instance remains visible while its close delay runs, but the backdrop disappears as soon as the final instance starts closing. A provider can override configured components for its subtree:

```tsx
<cue.OverlayProvider components={{ footer: DifferentFooter }}>{children}</cue.OverlayProvider>
```

## `cue.createOverlay<Props, Result>(render)`

```tsx
const dialog = cue.createOverlay<{ message: string }, boolean>((props, ctx) => {
  return (
    <Dialog open={ctx.open} onOpenChange={ctx.onOpenChange}>
      <DialogContent showBackdrop={false}>{props.message}</DialogContent>
    </Dialog>
  );
});
```

The callback receives:

```tsx
type OverlayContext<Components, Result> = {
  open: boolean;
  onOpenChange: (isOpen: boolean) => void;
  close: (options?: { result?: Result; delay?: number }) => void;
  components: Components;
};
```

`props` contains only the object passed to `open()` or `openAsync()`. Do not expect `open`, `close`, or `components` there.

### Handle methods

| Method               | Description                                                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `open(props?)`       | Opens one instance and returns that instance's `close` function. Props are required when `Props` has a required key.          |
| `openAsync(props?)`  | Opens one instance and returns `Promise<Result \| undefined>`. Dismissal resolves `undefined`.                                |
| `closeAll(options?)` | Closes every live instance from this overlay definition. A `result` settles every pending `openAsync()` from that definition. |

Closed instances always unmount after `delay`, which defaults to `300` milliseconds. There is no `unmount: false` option.

### Optional props

An overlay with no props or only optional props accepts a bare call:

```tsx
const settings = cue.createOverlay(() => <Dialog />);
settings.open();

const notice = cue.createOverlay<{ title?: string }>(() => <Dialog />);
notice.open();
notice.open({ title: "Hello" });
```

Required props remain required:

```tsx
const confirm = cue.createOverlay<{ message: string }>(() => <Dialog />);
confirm.open({ message: "Continue?" });
// confirm.open(); // TypeScript error
```

## Shared backdrop behavior

The provider renders no backdrop with no open overlays, one backdrop with one overlay, and still one backdrop for a stack. Closing the top overlay leaves the backdrop while the lower overlay remains. Closing the final instance removes it immediately, while the instance itself remains mounted until its delay expires. `closeAll()` follows the same rule.

## Breaking pre-v1 API change

The package does not export global `createOverlay`, global `OverlayProvider`, or `OverlayManager` values. Create one or more isolated Cue instances instead.
