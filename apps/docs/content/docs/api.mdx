## `createOverlay(component)`

Registers a component and returns a handle. Each `open` / `openAsync` creates a new instance. Optional generics: props `P`, result `R` (`createOverlay<P, R>`).

```tsx
const dialog = createOverlay((props) => <Dialog {...props} />);
const confirm = createOverlay<{ message: string }, boolean>((props) => <Dialog {...props} />);
```

| Method               | Description                                                                                                                                                      |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open(props?)`       | Open a new instance. Returns that instance's `close`. Props are required only when the props generic has a required key; all-optional props allow bare `open()`. |
| `closeAll(options?)` | Close every live instance of this overlay. `{ result? }` settles pending `openAsync`s. Always unmounts after `delay` (default 300ms).                            |
| `openAsync(props?)`  | Open a new instance. Returns `Promise<R \| undefined>` when you pass result generic `R`; otherwise `Promise<undefined>`. Dismiss → `undefined`.                  |
| `component`          | The component you passed in. Rare. See below.                                                                                                                    |

### Typed props

Pass a props generic when the overlay needs data at open time. If every key is optional, `open()` with no argument is allowed:

```tsx
export const confirmDeleteDialog = createOverlay<{
  organizationName: string;
}>((props) => <Dialog {...props} title={`Delete ${props.organizationName}?`} />);

confirmDeleteDialog.open({
  organizationName: "Atlas",
});
```

### `component`

<Callout type="warn" title="Escape hatch">
  You almost never need this. Call `open()`. Render the component yourself only when the overlay
  must sit inside a local tree that `OverlayProvider` does not wrap.
</Callout>

The provider mounts overlays at the root. That instance cannot see a page-level form context or a feature provider lower in the tree. Drive `open` and `onOpenChange` yourself and put the same component in that tree.

```tsx
function ProjectSettings() {
  const [open, setOpen] = useState(false);

  return (
    <ProjectForm>
      <button type="button" onClick={() => setOpen(true)}>
        Delete project
      </button>
      <confirmDeleteDialog.component
        open={open}
        onOpenChange={setOpen}
        close={() => setOpen(false)}
        organizationName="Atlas"
      />
    </ProjectForm>
  );
}
```

## `OverlayProvider`

Renders children plus every currently visible overlay. Mount it once near the root. Marked `"use client"` for Next.js App Router; see [Getting Started](/docs#nextjs).

```tsx
import { OverlayProvider } from "@vlkoss/cue";

<OverlayProvider>
  <App />
</OverlayProvider>;
```

## `OverlayProps`

```tsx
type OverlayProps<R = undefined> = {
  open: boolean;
  onOpenChange: (isOpen: boolean) => void;
  close: (options?: { result?: R; delay?: number }) => void;
};
```

Spread `open` and `onOpenChange` onto your dialog primitive. Call `close` from buttons (pass `{ result }` when you declared a result generic). Closing always removes the instance after `delay` (default 300ms).
