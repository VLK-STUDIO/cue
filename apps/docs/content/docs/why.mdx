---
title: Why Cue
description: Open the same overlay from distant UI or from code outside a component.
---

Local `useState` is the right tool when a dialog belongs to one screen and its opener sits next to it. Cue is for an overlay shared by distant UI or opened by code outside a component.

## One overlay, many callers

Create one Cue environment and one typed confirm dialog. Any client-side caller can open it:

```tsx
import { Button } from "@/components/ui/button";
import { Dialog, DialogContent, DialogTitle } from "@/components/ui/dialog";
import { CueBackdrop } from "@/components/cue-backdrop";

export const cue = createCue({ backdrop: CueBackdrop });

export const confirmDeleteDialog = cue.createOverlay<{
  organizationName: string;
}>((props, ctx) => (
  <Dialog open={ctx.open} onOpenChange={ctx.onOpenChange}>
    <DialogContent showBackdrop={false}>
      <DialogTitle>Delete {props.organizationName}?</DialogTitle>
      <Button variant="outline" onClick={() => ctx.close()}>
        Cancel
      </Button>
    </DialogContent>
  </Dialog>
));

// table row
confirmDeleteDialog.open({ organizationName: row.name });

// command palette
confirmDeleteDialog.open({ organizationName: selected.name });
```

Opening from another overlay uses the same Cue instance, so the provider keeps both instances in one visible stack.

## `open()` is not a hook

The handle is a plain object. `open()` works outside a component.

```tsx
export const sessionExpiredDialog = cue.createOverlay((_props, ctx) => (
  <Dialog open={ctx.open} onOpenChange={ctx.onOpenChange}>
    <DialogContent showBackdrop={false}>
      <DialogTitle>Session expired</DialogTitle>
    </DialogContent>
  </Dialog>
));

async function fetchProject(id: string) {
  const response = await api.getProject(id);

  if (response.status === 401) {
    sessionExpiredDialog.open();
    throw new Error("Unauthorized");
  }

  return response.data;
}
```

`cue.OverlayProvider` still has to be mounted. Call `openAsync()` when the caller needs a typed result. Dismissal resolves `undefined`.

## When not to use Cue

If the dialog belongs to one screen and nothing else needs that instance, keep local state. Cue adds a store and provider for a sharing problem you do not have.
