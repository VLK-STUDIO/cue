`@vlkoss/cue` gives your app one overlay environment. Create it once, define overlays from it, and mount its provider near the root.

## Installation

```npm
npm i @vlkoss/cue
```

### shadcn

The [shadcn registry](https://ui.shadcn.com/docs/registry) can add a local Cue configuration and shadcn's Dialog component:

The registry installs shadcn's `dialog` item first, then writes one local `cue` module containing the provider-level backdrop adapter and a typed map of shadcn Dialog components. Change that local configuration to fit the application.

The generated `content` component expects a small change to the local shadcn `DialogContent`. Add a `showBackdrop` prop, default it to `true`, and render `DialogOverlay` conditionally:

```tsx
function DialogContent({
  showBackdrop = true,
  ...props
}: DialogPrimitive.Popup.Props & { showBackdrop?: boolean }) {
  return (
    <DialogPortal>
      {showBackdrop && <DialogOverlay />}
      <DialogPrimitive.Popup {...props} />
    </DialogPortal>
  );
}
```

The generated `cue` module then forces `showBackdrop={false}` for every Cue overlay while the provider owns the single shared backdrop.

## Create the Cue environment

```tsx
// components/cue/index.tsx
import type { ComponentProps } from "react";
import { createCue } from "@vlkoss/cue";
import {
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogOverlay,
  DialogPortal,
  DialogTitle,
  DialogTrigger,
} from "@/components/ui/dialog";

type CueContentProps = Omit<ComponentProps<typeof DialogContent>, "showBackdrop">;

function CueContent(props: CueContentProps) {
  return <DialogContent {...props} showBackdrop={false} />;
}

function CueBackdrop() {
  return (
    <Dialog open>
      <DialogPortal>
        <DialogOverlay />
      </DialogPortal>
    </Dialog>
  );
}

export const cue = createCue({
  backdrop: CueBackdrop,
  components: {
    content: CueContent,
    footer: DialogFooter,
    header: DialogHeader,
    title: DialogTitle,
    description: DialogDescription,
    close: DialogClose,
    trigger: DialogTrigger,
  },
});
```

Each call to `createCue()` owns its own definitions, instances, provider, components, backdrop, and lifecycle state. Two Cue instances never share overlays.

## Add the provider

Mount the provider for that same instance once near the root:

```tsx
import { cue } from "./components/cue";

export function App() {
  return (
    <cue.OverlayProvider>
      <Page />
    </cue.OverlayProvider>
  );
}
```

The provider renders the overlay stack and one shared backdrop while at least one instance is open. It removes the backdrop immediately when the final instance starts closing, then keeps that instance mounted for its exit delay.

### Next.js

Put `createCue()` and overlay definitions in a client-side module. A server layout can render the provider:

```tsx
// app/layout.tsx
import { cue } from "@/components/cue";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <cue.OverlayProvider>{children}</cue.OverlayProvider>
      </body>
    </html>
  );
}
```

`createCue()` and `cue.createOverlay()` do not use hooks and are safe at module scope in client-side modules.

## Create an overlay

The first callback argument contains only values passed to `open()` or `openAsync()`. Cue runtime values are in the second argument.

```tsx
import { cue } from "@/components/cue";
import { Button } from "@/components/ui/button";
import { Dialog } from "@/components/ui/dialog";

export const settingsDialog = cue.createOverlay((_props, ctx) => {
  const { content: Content, title: Title } = ctx.components;

  return (
    <Dialog open={ctx.open} onOpenChange={ctx.onOpenChange}>
      <Content>
        <Title>Settings</Title>
        <Button variant="outline" onClick={() => ctx.close()}>
          Close
        </Button>
      </Content>
    </Dialog>
  );
});
```

Use configured components when an overlay needs them:

```tsx
const confirmDialog = cue.createOverlay<{ message: string }, boolean>((props, ctx) => {
  const { content: Content, footer: Footer, title: Title } = ctx.components;

  return (
    <Dialog open={ctx.open} onOpenChange={ctx.onOpenChange}>
      <Content>
        <Title>Confirm</Title>
        <p>{props.message}</p>
        <Footer>
          <Button variant="outline" onClick={() => ctx.close({ result: false })}>
            Cancel
          </Button>
          <Button onClick={() => ctx.close({ result: true })}>Confirm</Button>
        </Footer>
      </Content>
    </Dialog>
  );
});
```

## Open it

```tsx
const close = settingsDialog.open();
close();

const result = await confirmDialog.openAsync({ message: "Archive this project?" });
confirmDialog.closeAll();
```

`open()` returns a close function for that instance. `close({ result })` resolves its matching `openAsync()` call. If every props key is optional, both `open()` and `openAsync()` accept no argument.

For the cases Cue is meant to handle, read [Why Cue](/docs/why).
